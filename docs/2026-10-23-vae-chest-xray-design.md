# HW1 Design: VAE for Chest X-ray Generation

## Intent

Implement a variational autoencoder (VAE) in PyTorch, train it on the Kaggle
chest X-ray pneumonia dataset, generate synthetic chest X-rays, and evaluate them
with Inception Score (IS) and FID using pytorch-ignite. Deliverables, submitted to
Gradescope:

1. Code (reproducible end to end).
2. A 2-page NeurIPS-format report containing: hyperparameters, training loss
   curves, IS and FID, and example generated images. The report also states how AI
   was used.

## Prior work: Chandra et al., CENIM 2025

*Synthetic Chest X-ray Generation Using Variational Autoencoders for Pneumonia
Disease*, DOI 10.1109/CENIM67940.2025.11326136. The closest published work to this
homework: the same dataset, 64×64 images, a 128-d latent space and a
convolutional VAE.

What they did: 4 conv layers (4×4, stride 2, LeakyReLU; 64→128→256→512 channels)
and a mirrored decoder ending in tanh; RGB inputs scaled to [−1, 1]; MSE
reconstruction loss plus β·KL with β = 0.005; Adam, lr 1e-4, batch 32, 50 epochs
(TensorFlow, Colab T4). Evaluation: loss curves, a 2D latent projection,
interpolation, and judging samples by eye.

Weak spots that we avoid or improve on:

- **No FID or IS.** Sample quality is judged by eye only. We report both.
- **β = 0.005 is never examined.** A KL weight this small gives sharp
  reconstructions but leaves the aggregate posterior far from N(0, I), so samples
  drawn from the prior are worse than reconstructions. Their KL term settles
  near 600, which fits this. We run a β sweep.
- **Overclaimed latent structure.** They say Normal and Pneumonia separate
  clearly, but their Fig. 7 looks heavily mixed, and their "one latent direction
  controls lung transparency" claim has no figure. We only claim what our own
  plots show.
- Smaller issues: RGB for grayscale images, validation on the official 16-image
  split, a typo in the architecture table.

We cite it in the report as the closest prior work, and say what we add (FID/IS,
the β analysis, a prior-fit sampler).

## Goals

- A clean, readable VAE implementation that the user can explain.
- Reproducible runs: fixed seeds, a config saved with each run, and one command
  per stage.
- Every figure and number in the report is generated by the code, not filled in
  by hand.
- A measured answer to "how does β change sample quality?", which the prior work
  does not provide.

## Non-goals

- Making the samples state-of-the-art (VAEs are known to produce blurry samples;
  the report says so honestly).
- Generating images conditioned on class (NORMAL vs PNEUMONIA).
- Downstream classification experiments.
- Any CUDA or multi-GPU code.

## Anti-goals (a failure even if it runs)

- Made-up or hand-edited metric numbers in the report.
- A report longer than 2 pages of main content, or not in NeurIPS style.
- A missing or vague AI-usage statement.
- Latent-space or clinical claims that the plots don't support.
- Code that only runs on Claude's machine state (hard-coded absolute paths, or
  steps that are not documented).

## Approach (Claude's calls, open to change)

**Environment.** A `uv` project pinned to Python 3.12 (`requires-python =
">=3.12,<3.13"`). Dependencies: torch, torchvision, pytorch-ignite, scipy (needed
by ignite's FID), scikit-learn (Gaussian mixture, PCA), numpy, pillow,
matplotlib, pandas, pytest.

**Data.**
- Unzip into `HW1/data/`.
- The Kaggle archive contains a duplicate nested `chest_xray/chest_xray` folder
  and a `__MACOSX` folder. Use only `data/chest_xray/{train,val,test}`.
- The official val split has only 16 images, so it is ignored. Instead, a seeded
  10% split of `train` (≈520 images) serves as validation; the other ≈4,700 are
  used for training.
- `test` (624 images) is the real reference set for FID.
- Preprocessing: convert to grayscale, resize the short side to 64, center-crop to
  **64×64**, and convert to a tensor in [0,1].
- Light augmentation for training only: small random rotation (±5°) and small
  translation. No horizontal flip (it would mirror the anatomy, e.g. the heart
  side).
- Images are preprocessed once and cached as a uint8 `.pt` tensor so epochs stay
  fast.
- Resolution can be changed with a config flag (`--img-size 128`), but 64 is the
  default.

**Model.** `model.py`, a convolutional VAE.
- Encoder: Conv(1→64→128→256→512), kernel 4, stride 2, padding 1, with BatchNorm
  and LeakyReLU(0.2). This takes 64×64 down to 4×4×512, which is flattened. The
  channel widths match the prior work, which keeps the comparison simple.
- Two linear heads produce μ and log σ², with a **latent dimension of 128**.
- Reparameterization: z = μ + σ·ε.
- Decoder: Linear → 4×4×512, then ConvTranspose layers mirroring the encoder,
  ending in a sigmoid.

**Loss.** Reconstruction is BCE summed over pixels, averaged over the batch. The
total is reconstruction + β·KL, with the KL taken against N(0, I) in closed form.
For the main run, β is annealed linearly from 0 to its target over the first 10
epochs to avoid posterior collapse.

**Training.** `train.py`.
- Adam, lr 1e-3, batch size 128, 100 epochs, ReduceLROnPlateau on validation
  loss. (The prior work used lr 1e-4 and batch 32; with BatchNorm we expect the
  larger settings to train faster with similar results.)
- Each epoch appends train and validation values of {total, reconstruction, KL}
  to `runs/<name>/metrics.csv`.
- Saves `config.json`, the best and last checkpoints, and a fixed-noise sample
  grid every 10 epochs.
- Estimated time: under 1 hour per run on MPS at 64×64 (not yet measured; the
  first run will tell us).

**β sweep.** Train three runs with β ∈ {1, 0.1, 0.01}, everything else equal.
Because the BCE sum is over 4,096 pixels, the numerically small β values in the
prior work (0.005 with MSE) correspond to a different scale, so we sweep a range
and report how FID, reconstruction quality and KL move. The best-FID run becomes
the headline model. If time is short, run β = 1 first and add the others as time
allows.

**Evaluation.** `evaluate.py`.
- Sample N = 2,000 images with z ~ N(0, I) ("prior samples").
- Also sample 2,000 images from a **Gaussian mixture fit to the training-set
  latent means** (a 10-component mixture, following the ex-post density
  estimation idea of Ghosh et al., ICLR 2020), called "GMM samples".
- Use ignite's `FID` and `InceptionScore` metrics standalone (`update`/`compute`,
  following the linked ignite blog post).
- Images are repeated to 3 channels and bilinearly resized to 299×299 before
  going into InceptionV3.
- Also computes FID of the *reconstructions* of test images against the test
  set, as a reference point for what each model could reach at best.
- Results are written to `runs/<name>/eval.json`.
- Uses the same device rule as training (`mps` if available, else `cpu`). If
  InceptionV3 or an ignite op fails on MPS, set `PYTORCH_ENABLE_MPS_FALLBACK=1`
  so unsupported ops fall back to CPU, and tell the user.
- The report notes that IS is computed with ImageNet classes and carries little
  meaning for X-rays, and that FID with only 624 real images is biased upward.

**Figures.** `plots.py` produces:
- Loss curves (total, reconstruction and KL; train vs validation).
- An 8×8 grid of generated samples.
- Real images next to their reconstructions.
- A latent interpolation strip.
- Optionally, a PCA plot of test latents colored by class. We only describe
  class separation in the report if the plot shows it.

All figures are saved as PDF/PNG into `report/figures/`.

**Report.** `report/main.tex`, using the official NeurIPS 2025 style file
(downloaded into `report/`), compiled locally with `latexmk` (pdflatex is
installed).
- Sections: Introduction, Method, Experimental setup (hyperparameter table),
  Results (curves, β sweep and IS/FID table, samples), Discussion and
  limitations, References.
- References: Kingma & Welling 2014 (VAE), Kermany et al. 2018 (dataset), Heusel
  et al. 2017 (FID), Salimans et al. 2016 (IS), Ghosh et al. 2020 (ex-post
  density estimation), Higgins et al. 2017 (β-VAE), Chandra et al. 2025
  (closest prior work), pytorch-ignite.
- **AI usage statement:** a short section saying that Claude Code (Anthropic;
  Claude Opus 5.5 and Claude Sonnet 5.5 were used in this session) wrote the code
  and drafted the report, helped find and summarize related work, and that the
  student designed and directed the work, ran the experiments, checked the
  results, and edited the final text. Placed before the references; it may sit
  on page 2 or just after it. The user should check the wording against the
  course's AI policy.
- The author name and the "final vs preprint" style option are left as TODOs for
  the user.

**Layout.**
```
HW1/

  src/vae_xray/{data.py, model.py, train.py, evaluate.py, plots.py}
```

Running it: `uv run python -m vae_xray.train`, then `... evaluate`, then
`... plots`, then `latexmk` in `report/`. The README lists these commands.
